### 1. 폴란드 열병합발전소 OT 침해: private APN 횡이동으로 터빈·공정수 설비 정지

- 발행: 2026-08-11 15:55 KST
- 분류: Security | 태그: OT Security, Private APN, ICS, Siemens PLC, Network Segmentation
- 출처: [CERT Polska](https://cert.pl/en/posts/2026/08/incident-follow-up-report-energy-sector-2025/)

- 공개: CERT Polska가 2025년 12월 폴란드 열병합발전소 침해 후속 보고서를 공개, private cellular APN을 통한 OT 접근과 터빈·공정수 처리 설비 정지 확인
- 경로: 풍력발전 단지 VPN·router에서 client-to-client 통신이 허용된 APN으로 이동한 뒤, default credential이 남은 WAGO PFC200과 Siemens PLC를 거친 흐름
- 영향: 약 5만 명 난방 공급 설비에서 cogeneration이 단기간 중단됐으나 사업자 대응으로 고객 열·전력 공급 중단은 미발생
- 팀 액션: cellular APN을 OT 신뢰구간으로 보지 말고 client isolation·management interface 분리·MFA·default credential 제거·PLC STOP/factory-reset telemetry를 함께 점검

CERT Polska는 2025년 12월 발생한 폴란드 소규모 열병합발전소 침해의 후속 보고서를 2026년 8월 공개함. 공격자는 private APN에서 허용된 단말 간 통신을 이용해 별도 시설인 풍력발전 단지 경로에서 WAGO PFC200 controller와 발전소 OT network로 이동한 것으로 조사됨. 공격 중 Siemens S7-300·S7-1200·S7-1500 controller가 STOP mode로 전환되고 password protection이 적용돼 steam turbine과 process-water treatment system이 정지했으며, Moxa serial device server·switch 초기화와 unreachable IP 설정도 관측됨. CERT는 단일 CVE 또는 malware를 침해 원인으로 확정하지 않았고 router credential 획득 방식도 확인하지 못함. The Hacker News의 보도 시각은 2026-08-11 15:55 KST이며, 카드 정렬에는 이 secondary report RSS 시각을 사용함.

#### 무슨 일이 있었나

CERT Polska가 2025년 12월 폴란드 소규모 열병합발전소에서 발생한 침해의 후속 보고서를 공개

- 영향: steam turbine과 process-water treatment system 정지로 cogeneration 단기간 중단
- 공급: 약 5만 명 대상 열 공급 설비였으나 사업자 대응으로 고객 열·전력 공급 중단은 미발생

#### 본문 핵심 포인트

조사는 private APN의 client-to-client 통신 허용과 APN-reachable controller 관리면을 OT 침투 경로로 설명

- 경로: compromised wind-farm network에서 APN을 거쳐 default credential이 남은 WAGO PFC200 controller로 횡이동
- 행위: Siemens S7-300·S7-1200·S7-1500 controller STOP mode 전환과 password protection 적용
- 훼손: Moxa serial device server·switch 초기화와 unreachable IP 설정을 자동화 행위 가능성으로 조사

#### 확인된 범위와 한계

CERT는 단일 software vulnerability나 malware를 침해 원인으로 확정하지 않았으며, router credential 획득 방식도 미확인

- 경계: RUTX50 router의 published firmware vulnerability가 unauthenticated password 탈취를 제공한다는 증거는 미확인
- 경계: 공격 주체, 다른 시설의 동일 침해 여부, 모든 private APN 환경의 영향은 이 보고서로 확정 불가

#### 시사점

APN을 OT 신뢰구간으로 보지 말고 client isolation·management interface 분리·MFA·default credential 제거·OT allowlist를 함께 운영 필요

- 점검: APN client isolation과 device-to-device route, router·controller web/SSH 관리 interface 노출 범위 확인
- 탐지: PLC STOP, SSH tunnel, factory reset, network device IP 변경, VPN administrator login을 동일 incident timeline으로 상관 분석
- 복구: controller configuration backup·serial device inventory·out-of-band access·log retention을 OT recovery drill에 포함

- 시사점: APN client isolation, APN-reachable router·controller management service inventory, default credential 제거, VPN MFA, OT allowlist를 검증하고 PLC STOP·SSH tunnel·factory reset·network device IP 변경 로그를 동일 incident timeline으로 보존 필요.
